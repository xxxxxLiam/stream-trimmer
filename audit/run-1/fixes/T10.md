## 1. Owner gate in the packaged server (CRITICAL)
Cause: `channelRoutes.ts` read `process.env[name]` (a dynamic key, which esbuild `define` cannot replace) and
`build-server.cjs` defined nothing, so the packaged gate failed closed.
Change:
- `server/channelRoutes.ts`: `ownerSetting` now reads literal `process.env.VITE_OWNER_MACHINES` / `VITE_OWNER_SALT`
  (via `bakedSetting`), still preferring a runtime value and falling back to `.env` only outside the packaged app.
  The `deps.isOwnerMachine` override is untouched.
- `scripts/build-server.cjs`: when (and only when) `VITE_ENABLE_CHANNEL_DATA` is on, `define`s both values, read from
  the environment then `.env` the way Vite does. A public build defines nothing. Also added a `BUILD_SERVER_OUT`
  override so a test can build into a scratch folder instead of `electron/dist`.
- Defence in depth: in a public build `./channelRoutes` is the empty stub, so the module that names these
  settings is not bundled at all. Even forcing the `define` on for a public build (tried as a control) leaks nothing.

Hard constraint, proven. Both shapes built for real with the worst case in the shell
(`VITE_OWNER_MACHINES=<2 hashes>`, `VITE_OWNER_SALT=<salt>` exported for the PUBLIC builds too).
Counts are occurrences in the build output (web: `assets/*.js`; server: `server.cjs`):

| needle | web PUBLIC | web OWNER | server PUBLIC | server OWNER |
|---|---|---|---|---|
| the salt | **0** | 1 | **0** | 1 |
| machine hash #1 | **0** | 1 | **0** | 1 |
| machine hash #2 | **0** | 1 | **0** | 1 |
| `VITE_OWNER` | **0** | 0 (Vite inlines the value) | **0** | 4 |
| `api/channel/export` | **0** | 3 | **0** | 4 |

Public is 0 for every one. The owner server bundle contains the list and salt, and a runtime check of the real
bundles (spawned on a free port, `VITE_OWNER_MACHINES=*`): `POST /api/channel/export` with `{}` answers
**400** from the owner bundle (route live, gate passed, body rejected) and **404** from the public one.
Tests: `server/ownerBundle.test.ts` (3 tests: public has none of salt/hashes/`VITE_OWNER`/route; owner carries them;
owner answers 400, public 404). Those fail if the define is dropped (owner tests) and the public test would catch a
leak.

## 2. `export:save` owner check
New `electron/ownerCheck.cjs`: `createOwnerCheck({readMachineId, hashMachineId})` -> `{check(list, salt), isOwner()}`.
`owner:check` now delegates to it and the verdict is remembered in the main process; `export:save` returns
`{ok:false, error:"Could not save."}` (no hint the feature exists) unless `isOwner()`. The raw machine id and hash
never leave the module; only booleans cross the bridge, as before. `src/lib/ownerGate.ts` now always asks main,
including for a `*` list (previously skipped), so the verdict exists in a `*` build; `*` is honoured in main exactly
as the renderer honoured it. Same limit as the original gate: a device check, not a security boundary.
Tests (`electron/ownerCheck.test.ts`, 5): fail-closed before any check; match makes it owner and exposes only
`check`/`isOwner`; wrong hash / no salt / unreadable id / non-array stay non-owner; `*` without reading the id;
and a source-order test that `export:save` calls `ownerGate.isOwner()` before `saveExportFiles(`.
Not exercised end to end: the IPC handler itself needs a running Electron main with a non-owner build; the
wiring test pins the order instead.

## 11. "Clear partials"
Behaviour already respected protection (T1: `clearCache` skips in-use and held folders); the lie was that the count shown
counted those protected folders as "partial downloads" and the label promised partials only. Fixed both ends:
`cacheUsage()` now counts only what Clear would remove and also returns `protectedFolders`; the button reads "Clear
unfinished" and the note says "unfinished downloads ... Clearing leaves anything still running, and clips waiting to be
saved, alone." Test: with an idle folder (100 B), a folder in use (1000 B) and a held finished clip (5000 B), usage is
`{folders:1, bytes:100, protectedFolders:2}`, Clear removes exactly that, and the finished clip and the running partial survive.
