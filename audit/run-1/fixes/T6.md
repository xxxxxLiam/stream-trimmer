New tests: `src/lib/youtubeConnection.test.ts`, `src/components/YouTubeConnectModal.test.tsx`.

## Order: escape route and trap land together
Both are in the one modal change. The trap effect (`gated`) and the Escape handler share a
`keydown` listener, and the visible "Continue without signing in (360p)" button is the first
Tab stop. There is no state of the tree with the trap and no route out.

## A-1 (blocker) — fixed
- Cause: the modal's only exits were a successful connection or nothing; `open` is
  `!connected || restoring` (App.tsx), so a signed-out user could never clear it.
- Change: `skipped` flag in the connection store (`continueSignedOut()`, `resumeSignIn()`;
  set only while not connected, cleared by any successful sign-in, lasts for the app
  session, never feeds `cookiePayload`). The modal renders nothing while `skipped`. A button
  "Continue without signing in (360p)" plus Escape set it. Copy under the button says videos
  download at 360p until signing in and that you can sign in later from the header chip.
  App.tsx is untouched (the modal hides itself).
- Return to sign-in: the header chip already shows "Not signed in" and its menu has
  "Import cookies.txt" (verified chip state after skipping in the real app).
- Tests: lib `continueSignedOut hides the gate without connecting; resumeSignIn brings it back`;
  modal `offers a labelled signed-out route and hides once it is taken`.
- Negative control: no-op `continueSignedOut` -> lib test FAILS (1 fail); button text
  removed -> modal test FAILS; `if (state.skipped) return null` removed -> modal test
  FAILS. Restored: all pass.

## H-2 (major) — fixed
- Cause: `aria-modal` was markup only. Nothing took focus, set `inert`, or handled keys.
- Change: while the full dialog is showing, an effect (a) focuses the dialog (tabIndex -1,
  labelled by its title), (b) sets `inert` + `aria-hidden` on the dialog's siblings and
  restores them on cleanup, (c) wraps Tab/Shift+Tab inside the dialog as a backstop,
  (d) Escape -> continue signed out, (e) restores prior focus on close.
- Verified in the real Electron app under xvfb (scratch build of HEAD + these two files):
  - Fixed: initial focus = dialog (`DIV Sign in to YouTube`); background siblings
    `inert=true aria-hidden=true`; Tabs 1..40 cycled Continue -> Pick a browser ->
    Diagnostics -> Continue ... **0 of 40 outside the dialog** (Choose cookies.txt and
    Check browsers are disabled while the sweep runs, so correctly skipped); Escape removed
    the dialog, chip read "Not signed in", no `[inert]` left in the document.
  - Negative control (trap effect disabled, rebuilt): initial focus `BODY`, background
    `inert=false aria-hidden=null`, **36 of 40 Tabs outside the dialog**, Escape left the
    dialog up. Restored.
- Unit test: the SSR test asserts `role=dialog`, `aria-modal`, `tabindex=-1` (can take
  focus). Focus/inert are DOM behaviour with no jsdom in this repo, so they are covered by
  the driven run above rather than a unit test; I did not add jsdom.

## A-2 (major) — fixed
- Cause: `sweepBrowsers` awaited per-browser checks and, on return, wrote its own result
  (failure message, `connected:false`, or `markConnected(browser)` replacing `source:"app"`)
  with no knowledge of a sign-in made meanwhile.
- Change: a `signInEpoch` counter bumped in `markConnected` and at the start of
  `verifyImported`. The sweep captures it at start and, after each `await checkSource`
  (and before each iteration), returns without writing if it moved.
- Tests: `a sweep that returns after a cookies.txt sign-in must not overwrite it` (import
  completes mid-sweep, sweep then returns negative for every browser: still connected,
  source `app`, no "None of your browsers" message) and `a late sweep SUCCESS also must not
  replace the imported source`.
- Negative control: guards removed -> both A-2 tests FAIL (1 passed, 2 failed). Restored:
  3/3 pass.
- Known edge: an import that is still verifying when the sweep ends does not stop the
  sweep's own end-of-run state write unless the epoch has already moved (it moves at
  verification start, so the window is only the file read before that). Not chased.
