(`.cols-host` / `@container (min-width: 960px)`, unlayered so it beats the max-h/max-w utilities). Side effect that
is also a fix: with the 400px help drawer open the area is measured without the drawer, so it no longer
crushes three columns into what is left. Column bases are now 280 / 420 / 260 (was 320 / 520 / 280), maxes 400 / 360.

scrolling area, which is keyboard-focusable (role=region, tabindex 0).

## B-3
Cause: PreviewPanel's root was `flex-1 min-h-0` inside the centre column, which scrolls at three columns, so the
flex algorithm shrank the panel below its fixed-ratio child and the 458px video box spilled over the mark bar.
Change: root is `shrink-0` (no flex-1/min-h-0); every direct child of the centre column is `[&>*]:shrink-0`; the video box
is capped at `max-w-[80vh]` and centred so it cannot eat the whole height (342px tall at 1100x760). The centre column
is the scroller, so nothing is covered. Measured: Add and In field OK with 5 segments at 1100, 1280, 1440.

## E-1
Cause: AppHeader tested the runtime prop; App passed `screen/onScreen/channelAvailable` unconditionally and
branched on `screen === "channel"`. Change: AppHeader gates every channel reference on CHANNEL_DATA_BUILT (the
compile-time constant derived from `__CHANNEL_DATA__` in lib/ownerGate.ts; used instead of the bare identifier so the
tsx tests, where nothing defines `__CHANNEL_DATA__`, do not throw). The props are optional, and App only supplies them
through `{...(CHANNEL_DATA_BUILT ? {...} : null)}` and tests `CHANNEL_DATA_BUILT && screen === "channel"`.
