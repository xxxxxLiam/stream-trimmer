# T4 — clip state

Not verified in the real app (no harness run: other threads were rebuilding product files
at the same time, and YouTube is unreachable). Evidence is unit tests plus negative controls.
Node has no DOM here (no jsdom), so effects and event handlers are tested through the pure
functions they call, plus source-wiring assertions where noted.

## B-1 transcript search crash
- Cause: `active` is reset in an effect, so for one render after the result set shrinks
  `matches[active]` is undefined; `activeMatch !== null` passed and `.line` threw.
- Change: `pickActiveMatch(matches, active)` bounds-checks; the column uses it.
- Test: `src/components/TranscriptColumn.test.ts` (stale index with empty matches, and wiring).
- Negative control: unbounded helper -> 2 fail; inline the old expression in the column -> wiring test fails. Restored: pass.
- Not done: `useTranscriptWindow.ts` (not mine) should also clamp `active`.

## B-2 + C-1 shared module store
- Cause: one module-level `state` for all tabs while App mounts every tab.
- Change: `createSegmentStore()`; `TabActiveProvider` (WorkspaceContext.tsx) creates one store per
  tab and provides it via `SegmentStoreContext`; `useSegments()` reads it. `setBanked` ignores an
  identical plan (what let two writers loop). Legacy module functions (`setPlayhead`,
  `setBankedRanges`, `clearSegments`, ...) now act on the ACTIVE tab's store.
- Test: `src/hooks/useSegments.test.ts` (tab isolation, no cross-notification, idempotent banked).
- Negative control: store made a singleton -> 3 fail; dedupe removed -> 1 fail. Restored: pass.
- PARTIAL for C-1 until two non-owned edits land (see below): ClipsColumn still calls the legacy
  `setBankedRanges`, which writes to the active tab's store even from a hidden tab. I reasoned it
  converges (no loop) but a hidden tab's own plan is not painted until it is fixed; not exercised in React.

## B-5 URL with no video id
- Cause: `/api/info` accepts channel/playlist URLs; `loadInfo` never checked `extractVideoId`.
- Change: `videoUrlProblem(url)`; `loadInfo` sets info=null and an error; `download` refuses too.
- Test: `src/hooks/useClipper.test.ts`. Negative control: helper accepts everything -> fail; loadInfo check removed -> wiring test fails.

## B-6 Cancel does not stop the engine (renderer half)
- Change: `download` keeps the jobId; `cancelDownload` aborts the fetch AND posts
  `POST /api/download/cancel` with `{ "jobId": "<id>" }` (best effort, errors swallowed).
- ASSUMPTION for T1/G-10: that route and body (same shape as the channel exporter's cancel).
  If T1 instead kills on `res.on("close")` alone, the abort already does it and the extra POST is harmless (404 ignored).
- Test: `requestEngineCancel` posts the right thing / survives failure; wiring test. Negative control: post removed -> fail; call removed from cancelDownload -> fail.
- Not verified against a real engine.

## B-7 delete mid-cut still in the file
- Cause: edits stayed live while the cut ran on a snapshot.
- Change: store has `locked`, set from `downloading` by TabBridge; remove/move/load/add refused while locked (`clear` stays allowed, it is how the finished cut empties itself). SegmentList disables the x, dragging and Delete/Alt-arrow while locked.
- Tests: `useSegments.test.ts` (lock), `SegmentList.test.tsx` (SSR markup). Negative control: lock check removed from `remove` -> fail; `disabled` removed -> fail.

## B-8 tab remembers nothing
- Change: tab record now persists `url` and unsaved `segments`; TabBridge restores them on mount
  (sets the url, restores segments with their video id so `syncVideo` does not wipe them) and reports
  changes. Closed tabs go on a stack (10); Ctrl/Cmd+Shift+T reopens at the old position with its work
  (`reopenTab`, `closedCount` exposed). Closing a tab with marked segments asks first.
- Test: `src/context/WorkspaceContext.test.ts` (round trip, junk rejected, work recording, reinsertion).
- Negative control: url dropped from `cleanTab` -> 2 fail; reinsert guard removed -> fail.
- Not tested: the React restore effect and the confirm dialog (no DOM). Restored tabs load their
  info on relaunch (existing debounced auto-load), one request per tab.
