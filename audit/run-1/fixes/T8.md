## F-3 help button

Cause: header is a `z-30` stacking context; Copy blocks, Symbols, sign-in modal and restoring overlay are `z-50`.
Live probe: Copy blocks and Symbols open, click on `#ui-help-button`: before both time out, drawer not opened;
after both click and the drawer opens.
- `HelpButton.tsx`: a placeholder keeps the header slot; the real button is portalled to `document.body`
  (z 70) over the placeholder and follows it on resize/wrap/DOM change. Keeps `id="ui-help-button"`.
- `CopyBlocks.tsx`: `z-20` (under the header) and it moves left of the help drawer when that is open.
- `HelpDrawer.tsx`: `relative z-[55]` so it shows above the sign-in scrim and panels.
Not checked live: the first-run sign-in modal itself (the harness boots signed in); covered by the z-order
test. Side effect: Tab order puts the portalled "?" last in the document. Symbols (`SymbolPalette.tsx`, not mine)
is `z-50` and will overlap the open drawer; its owner should shift it as CopyBlocks does.

## F-7 and the escaped pattern

Cause: `DownloadBar` printed `error` raw. Now `displayError()` (redact with the failure's `homeDir`) feeds both
the alert (`FailureAlert`, exported) and the status line.
Planted 9 markers (cookie header, cookie row, bearer, access_token, po_token, signed URL with stream id,
email, home path, cookies path), shapes only:

| surface | before | after |
|---|---|---|
| on-screen alert | 7 of 9 (the other two were dropped by the engine's tail) | 0 of 9 |
| Copy diagnostics clipboard | 1 of 9 | 0 of 9 |

Shapes after: `Authorization: <redacted>`, `access_token=<redacted>`, `...&id=REDACTED&sig=REDACTED...`,
`<email>`, `~/Videos/...`, `--cookies <redacted>`.
Escaped pattern: the googlevideo stream `id=` query parameter (`SENSITIVE_PARAM_EXACT` had `s, ip, si, n`;
`sid` matched but `id` did not). Added `id`. Also added a `/root` rule (Linux root's home has no user
segment, so it leaked when `homeDir` was not supplied, e.g. pre-flight failures).
Unit tests: `DownloadBar.test.tsx` (0 of 9 in the rendered alert, with and without diagnostics),
`diagnostics.test.ts` (id param, `/root`, 9 of 9 in one pass).

Main-process copy: `electron/redact.cjs` (T2) already contains both rules (`id`, `/root`), so
`electron/redact.test.ts` passes (2 pass); I did not edit that file. Proposal for consolidation: one shared
implementation (e.g. a plain `.cjs` module imported by both sides) instead of two copies.

## F-8 Copy diagnostics gating

Cause: a cookie-store failure returns 400 with no `code`; `classifyFailureKind(undefined)` is "developer".
Live (real "could not find chrome cookies database" via stub): before the button showed beside "Your in-app
YouTube sign-in is no longer valid..."; after no button. A code-level failure (`unknown`, download stage)
still shows it.
Change: new `offersDeveloperDiagnostics(code, message)` in `diagnostics.ts` — true only when the engine sent a
code that is not user-fixable; no code is not code-level, except the renderer's own "transfer broke" sentence
(`TRANSFER_BROKEN_PREFIX`), which has no engine code and tells the user to copy diagnostics.
`classifyFailureKind`/`needsDeveloper` unchanged (their tests stay). Consequence: a code-less unexpected
error (plain 500 `{error}`) no longer shows the button; if the owner wants those, the engine should send
`code`. `useClipper` could set a code for the transfer failure instead of the prefix match.
