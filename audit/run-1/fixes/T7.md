## E-2 (blocker) — fixed
Cause: the live checkpoint lived in `ytchan-<hash>`, the prefix `clearCache` sweeps; and
`appendJsonl` swallows errors, `writeCsvFromJsonl` returns 0 rows for a missing source, so a vanished
file was read as "nothing collected".
Change (both halves, independent of whether T1 still deletes): checkpoints now use
`ytchanwip-` (not matched by `startsWith("ytchan-")`), with an own 7-day stale sweep since resumeCache
no longer sees them. Live files are created empty up front, appended with a strict
`appendCheckpoint` (missing file or ENOENT -> `CheckpointLostError`), and re-checked before the CSVs
are streamed. A resumed checkpoint with a missing live file is discarded instead of resumed into a hole.
The error says nothing was saved. Response is a 500, never a 200 with 0 rows.
Tests: "clearing the cache mid-export does not empty the CSVs" (cache cleared mid-run -> 200, comments.csv
18 rows, transcripts.csv 12 rows via scanCsvFile), "a checkpoint that vanishes mid-run is an error",
"only the comments file vanishing is also caught", "uninterrupted export unchanged" (rows + sha256 equal
across two runs).
Before (unfixed): clear mid-run -> comments.csv 0 rows (expected 18); vanished checkpoint -> HTTP 200
`{"videos":6,"comments":0,"transcripts":0}`.
Negative control: prefix reverted -> clear test FAILS (`500 !== 200`); strict append + build check
reverted -> both vanish tests FAIL. Restored, all pass.

## E-3 (blocker) — fixed (refused, server-side)
Cause: same request = same checkpoint folder; both appended (33 rows vs 18 expected), or the first to
finish deleted the folder under the second (header-only CSVs). Per-tab providers are in App.tsx (not mine),
so the guard is where all tabs meet.

`data.error`. The empty-overwrites-full part is also closed by E-5's unique folders.
Tests: "two identical exports at once are isolated or refused", "a refused duplicate leaves the running
export's checkpoint alone" (running export still 18 rows, slot free afterwards), "different requests still
run side by side". Before: 33 !== 18.
Negative control: refusal disabled -> both E-3 tests FAIL. Restored, pass.

## E-4 (major) — partial
Change: all three routes (`export`, `cancel`, `progress`) are wrapped in `ownerOnly`, which calls `next()`
for a non-owner, giving Express's own 404, identical to a route that does not exist (no message). Decision:
`VITE_OWNER_MACHINES` / `VITE_OWNER_SALT` (env, or .env when running from source) against the
salted hash of the id from electron/machineId.cjs, read inside the main process; `*` admits any machine;
empty list, no salt or unreadable id fails closed. Optional `deps.isOwnerMachine` override. Only a
boolean is used; `owner:check` is untouched. The check module is imported by channelRoutes.ts only, so a
public build (stub alias) does not bundle it from here.
Tests: off-list hash -> 404 on all three routes, no yt-dlp call, no checkpoint, same as an unknown route;
empty list -> 404; the real machine's hash (upper-cased, in a list) -> 200.
Negative control: gate disabled -> both closed-gate tests FAIL. Restored, pass.
Blocked / needs others (not my files):
- `export:save` in electron/main.cjs (and exportSave.cjs) has no owner check. With the routes gated
  nothing legitimate produces the CSVs, but the IPC still moves any `ytchan-` folder. Needs
  `ipcMain.handle("export:save")` to refuse when the existing owner check says no (T3/shell owner).
- The packaged server needs the list and salt: scripts/build-server.cjs must `define`
  `process.env.VITE_OWNER_MACHINES` / `VITE_OWNER_SALT` (as it does for the channel flag), or index.ts must
  pass `isOwnerMachine` in the deps. Until one of those lands, an owner-enabled PACKAGED build fails
  closed (the tool is hidden by the server, not just the UI). Source/dev runs and tests read env/.env.
